Documentação de Negócio

Visão Geral

A Hat Store é uma loja virtual especializada em chapéus, permitindo que clientes naveguem por produtos, filtrem por categoria e preço, adicionem itens ao carrinho, realizem compras e consultem seus pedidos. O sistema é composto por um frontend em HTML/CSS/JS e um backend em Go, com autenticação JWT e integração de métodos de pagamento fictícios (PIX e boleto).

Catálogo de Produtos

O sistema possui 15 chapéus divididos em 3 categorias:

  • Importados (9 produtos): Panamá, Fedora, Bucket, Cowboy, Floppy, Bowler, Beanie, Pork Pie, Trilby
  • Nacionais (5 produtos): Snapback, Sertanejo, Gaúcho, Cangaceiro, Pescador
  • Crescer (1 produto): Chapéu Gustavo Carvalho

Faixa de preço: R$ 29,90 (Pescador) até R$ 150,00 (Fedora)

Fluxo de Funcionamento

  1. Cadastro e Login: O usuário pode criar uma conta informando email e senha. O sistema possui proteção contra ataques de força bruta (bloqueio após 5 tentativas em 15 minutos). Tokens JWT expiram em 24 horas (ou 30 dias com "Lembrar-me").
  2. Validações de Registro (new_hatstore): Nome (mín. 3 caracteres), CPF (único, formato 000.000.000-00), data de nascimento (idade mínima 18 anos) e senha forte (8+ caracteres com maiúscula, minúscula, número e caractere especial) são obrigatórios.
  3. Listagem de Produtos: Todos os chapéus são exibidos na página inicial. O usuário pode filtrar por categoria (nacional, importado, crescer) e faixa de preço (mínimo/máximo).
  4. Controle de Estoque: Produtos sem estoque são exibidos como "Indisponível" e não podem ser adicionados ao carrinho. O estoque é descontado atomicamente ao finalizar pedidos.
  5. Carrinho de Compras: O cliente adiciona chapéus ao carrinho, ajusta quantidades e aplica cupons de desconto (ex: HATOFF para 25% off no primeiro pedido).
  6. Checkout: Para finalizar a compra, o usuário preenche dados pessoais, endereço e escolhe o método de pagamento (PIX ou boleto). O cupom HATOFF só pode ser usado uma vez por CPF.
  7. Registro do Pedido: O pedido é enviado ao backend, que valida estoque, calcula o total (aplicando descontos se aplicável) e armazena no banco de dados PostgreSQL.
  8. Cálculo de Frete (new_hatstore): O frete é calculado automaticamente com base no CEP do cliente. A 1ª unidade paga o custo base da região; unidades adicionais somam 30% (2ª), 20% (3ª) e 10% (4ª+ ) do custo base. Se o CEP não for atendido, o pedido é recusado.
  9. Consulta de Pedidos: O cliente pode consultar o histórico de pedidos informando o CPF na página dedicada ou na sidebar da home.
  10. Meus Pedidos (new_hatstore): Usuários logados podem consultar seus pedidos na página "Meus Pedidos", que exibe automaticamente todos os pedidos associados ao email autenticado, incluindo valor do frete.
  11. Perfil do Usuário (new_hatstore): O endpoint /api/me retorna nome, email, CPF e data de nascimento do usuário autenticado.

Regras de Negócio

  • O cupom HATOFF concede 20% de desconto apenas no primeiro pedido de cada CPF. Tentativas de reutilização retornam erro 409 (Conflict).
  • Pedidos só podem ser registrados por usuários autenticados (token JWT válido).
  • Dados obrigatórios: nome, CPF, email, telefone, endereço, número, bairro, CEP, cidade, UF, método de pagamento.
  • Validações de formato: CPF (000.000.000-00), telefone ((99) 99999-9999), CEP (00000-000).
  • Com new_hatstore: o desconto HATOFF é aplicado apenas sobre os itens; o frete é somado depois ao total.
  • O estoque é verificado antes de descontar. Se não houver estoque suficiente, retorna erro 409 (Conflict).
  • Pedidos, usuários e estoque são armazenados no banco de dados PostgreSQL (Neon), com persistência total entre reinícios.
  • O estoque de cada chapéu pode ser editado via API (0 a 200 unidades).

Principais Funcionalidades

  • Autenticação de usuários: Cadastro e login com JWT. Proteção contra força bruta. Opção "Lembrar-me" para sessão de 30 dias.
  • Registro avançado (new_hatstore): Nome, CPF (único), data de nascimento (18+) e senha forte obrigatórios. Email validado por regex. CPF e email não podem ser duplicados.
  • Filtro avançado de produtos: Filtre por categoria (múltipla seleção) e faixa de preço. Pesquisa por nome.
  • Gerenciamento de carrinho: Adicione, remova e ajuste quantidades. Cupom HATOFF aplicável (25% off).
  • Checkout seguro: Validação completa de dados. Métodos de pagamento: PIX (código copia-e-cola) ou Boleto.
  • Cálculo de frete (new_hatstore): Frete calculado automaticamente pelo CEP no checkout. Consulta disponível via GET /api/frete?cep=...&quantidade=....
  • Consulta de pedidos: Histórico completo por CPF com detalhes de itens, valores e status.
  • Meus Pedidos (new_hatstore): Página dedicada para usuários logados consultarem seus pedidos com valor de frete exibido.
  • Perfil do usuário (new_hatstore): Endpoint /api/me para consultar dados do perfil autenticado.
  • Gestão de estoque: Visualização e edição do estoque via API dedicada.
  • Auditoria: Registro automático das ações de login, registro de usuário e criação de pedidos. Logs incluem IP, email e detalhes da operação, com limpeza automática após 30 dias.
  • Documentação Swagger: Disponível em /swagger/index.html.

API - Rotas Disponíveis

Autenticação (públicas)

  • POST /auth/register - Criação de conta de usuário
  • POST /auth/login - Autenticação (retorna token JWT)

Produtos (públicas)

  • GET /api/hats - Listagem de chapéus (suporta filtros: categoria, min, max)
  • GET /api/estoque - Listagem do estoque atual
  • PATCH /api/hats/{id}/estoque - Editar estoque de um chapéu
  • GET /api/frete?cep=...&quantidade=... - Consulta de frete por CEP e quantidade
  • GET /api/feature-flags - Feature flags ativas

Pedidos (protegidas - requer JWT)

  • POST /api/pedido - Registrar novo pedido
  • GET /api/pedidos?cpf=... - Consultar pedidos por CPF
  • GET /api/meus-pedidos - Pedidos do usuário logado (JWT)

Perfil (protegida - requer JWT)

  • GET /api/me - Dados do perfil do usuário autenticado

Observações Técnicas

  • Frontend utiliza localStorage para carrinho, token JWT e email do usuário.
  • Backend em Go com gorilla/mux. Rotas protegidas por middleware JWT.
  • Banco de dados PostgreSQL (Neon) com GORM como ORM. Operações de estoque são atômicas via transações SQL.
  • Sistema de auditoria registra login, registro e pedidos no banco com IP, email e detalhes em JSON. Logs antigos (30+ dias) são removidos automaticamente.
  • Deploy automatizado via Fly.io. Testes executados antes do deploy.
  • Documentação Swagger gerada automaticamente via swaggo/swag.
  • Feature flags gerenciadas via tabela settings no banco, com cache em memória atualizado a cada 30 segundos.
